# 假設與決策紀錄

## 預設決策（來自《00_總覽與共同規範》F 節）
| # | 項目 | 預設決策 |
|---|------|----------|
| 1 | 一般抽號 vs 付費抽號 | 主持人按「抽號」為**免費一般抽**（paid=false）；「付費單抽／連抽」由玩家付 10 元／次（paid=true），列入彩池。 |
| 2 | 名次如何產生 | 玩家用紙卡，網頁無法自動判賓果。主持人在抽號頁按「🎉 第 N 名賓果」登錄名次，並可填「同時賓果人數」。 |
| 3 | 暗控機率是否含免費抽 | 對所有抽號生效（免費＋付費），連續無效上限 4 次，第 5 次必定為新有效號。機率參數放 `defaults.js`，方便調整。 |
| 4 | 全部 75 號抽完 | 禁用抽號按鈕，提示「號碼已全部抽出」。 |
| 5 | 同時賓果 | 例：2 人同為第 1 名 → 平分「第1名＋第2名」獎金，下一名次直接為第 3 名。 |
| 6 | 撤回 | 僅能撤回「上一筆」，可連續撤回；撤回 `paid:true` 紀錄時 `paidDrawCount` 與彩池同步扣回；撤回 repeat／blank 同步還原 `invalidStreak`。 |
| 7 | 安慰獎顯示 | 第 2 名登錄後才在畫面顯示安慰獎資訊。 |
| 8 | 規則透明度 | 規則說明頁加一行「主持人保留依現場情況調整抽號機率與結算比例之權利」。 |

## 階段 3 追加決策
| # | 項目 | 決策 |
|---|------|------|
| S3-1 | 當期安慰獎單價 | `min(設定金額, 續卡>新卡 ? 30 : 設定金額)`。預設設定 50 時與規劃書一致（50／30）；若主持人把設定金額調高，不會被硬壓回 50，只在續卡>新卡時降到 30。 |
| S3-2 | 得獎人數 | 已登錄名次的 tieCount 加總，再加上尚未登錄的名次各 1 人；未登錄任何名次時為 3。未得名人數 = `max(0, players − 得獎人數)`（例：第 1 名 1 人＋第 2 名 3 人同時 → 得獎 4 人）。 |
| S3-3 | 強平判斷用的「第 3 名獎金」 | 以結算的第 3 名名次獎金（未拆分前）為準。若同時賓果讓多人平分第 2、3 名，每人實領可能低於安慰獎單價，這是已知限制。 |
| S3-4 | `settle` 欄位 | 依規格輸出，另加 `prizePool`（前三名總獎金池）與 `unrankedPlayers`。`prizeTotal` 為實發前三名獎金（各名次已捨去）；`remainder` 以各名次原獎金計算。同時賓果平分時的捨去尾差，由 `calcPayoutTotal` 與 `settle` 結果相減得出，階段 4 結算收據時併入主持人零頭。 |
| S3-5 | 壓力值公式 | 以「可分配彩池 ÷ 讓第 3 名獎金 > 安慰獎單價所需的最低可分配彩池」為比值 r：r ≥ 1.5 → 0；1 ≤ r < 1.5 → 0~0.5 線性；r < 1 → 0.5~1 線性（彩池 0 → 1）。比例中第 3 名為 0% 時固定為 1。門檻 1.5 在 `FINANCE.comfortRatio`。 |
| S3-6 | 登錄名次條件 | 遊戲進行中、至少抽過一次、名次未滿，且上一次登錄之後必須又抽過號（同一次抽號不能登錄兩個名次，需用「同時賓果人數」）。 |
| S3-7 | 取消名次登錄 | 新增 `retractLastRank`（抽號頁「取消上一個名次登錄」），登錄錯誤時使用；撤回抽號仍會自動移除失效名次。 |
| S3-8 | 簡易獎金池顯示 | 只顯示總彩池、付費抽次數、預估前三名獎金、已登錄名次的每人實領，以及第 2 名出爐後的安慰獎（每人金額與人數）。不顯示辛苦費與任何調降資訊，console 無輸出。 |

## 階段 5 追加決策
| # | 項目 | 決策 |
|---|------|------|
| S5-1 | 連抽播放方式 | `paidDraw` 一次算出全部結果，再每 `BATCH_PLAY_INTERVAL_MS`（800ms）用 `appendRecords` 逐筆寫入 state，彩池與付費次數隨之逐筆增加。播放中若重新整理頁面，尚未播放的筆數不會寫入（也不會計費）；若局面被改動（如重新開始）則中止。 |
| S5-2 | 連抽次數輸入 | 用 − N + 步進器而非自由輸入，上限為 `min(連抽上限, ⌊單次付費上限 ÷ 單抽單價⌋)`（`maxBatchCount`），所以 11 次或超過 100 元根本無法選取。 |
| S5-3 | 撤回確認 | 每次撤回都需確認；付費紀錄提示退回 `drawPrice` 元；連抽中的單筆可個別撤回（core 本來就是逐筆撤回）。 |
| S5-4 | 名次登錄介面 | 點「🎉 第 N 名賓果」開彈窗，內含同時賓果人數（1~參加人數）與說明；名次登錄不可在同一次抽號重複（沿用 S3-6）。名次全滿或本次抽號已登錄時，只要已有名次，按鈕仍可開啟，用來「取消上一個名次登錄」。 |
| S5-5 | 結束遊戲 | 先二次確認，再顯示佔位彈窗；階段 7 才接結算收據，因此本階段**不變更** `game.status`。 |
| S5-6 | 驗卡呈現 | 有效號碼依輸入順序（去重）逐筆顯示；無效輸入另列在後。「第幾次」為該號碼首次出現的抽號序，重複出現時另註記次數。電腦版以彈窗開啟（不離開抽號畫面），手機為分頁。 |
| S5-7 | 獎金池顯示 | 已出爐名次顯示每人實領；同時賓果併入的名次顯示「併入第 N 名平分」；未出爐名次顯示「預估」。已抽出張數置底。左欄不顯示辛苦費與零頭。 |
| S5-8 | 手機抽號分頁 | 不再顯示彩池（改由獎金池分頁查看），讓抽號操作區更短。 |

## 階段 7 追加決策
| # | 項目 | 決策 |
|---|------|------|
| S7-1 | 新增 `core/receipt.js` | 規劃框架未列此檔，但收據需要可在 Node 測試的純邏輯：`endGame`、`buildReceipt`、`receiptSum`、`receiptToText`。`ui/receipt-view.js` 只負責畫面。 |
| S7-2 | 金額守恆與「零頭」 | 零頭 = 總彩池 − 辛苦費 − 前三名實發 − 安慰獎實發，涵蓋：名次獎金捨去至 10 元的尾差、同時賓果平分的尾差、**未被登錄名次的獎金**。零頭歸主持人。公式恆成立：總彩池 = 辛苦費 + 前三名實發 + 安慰獎 + 零頭。 |
| S7-3 | 未登錄任何名次就結束 | 前三名各列「無人得獎」，前三名獎金池併入零頭（主持人所有）。安慰獎仍沿用 `settle` 既有規則（得獎人數以 3 人計，人數 − 3 的玩家領安慰獎），與「只登錄 1～2 名就結束」的處理一致。 |
| S7-4 | 收據不顯示調降 | 收據只顯示 `settle` 的最終結果（辛苦費金額、安慰獎單價×人數），**不顯示辛苦費 %**，也不讀取 `adjustments`；文字版收據同樣不含警告字樣（測試驗證）。 |
| S7-5 | 結束後的操作 | `status='ended'` 後抽號、連抽、撤回、名次按鈕沿用既有 `playing` 判斷自然禁用；抽號頁「結束遊戲」按鈕改為「🧾 查看結算收據」，頂部另有「🧾 收據」（僅結束後顯示），重新整理後仍可重開。 |
| S7-6 | 開新局 | 二次確認後呼叫 `reset()`，並停留在設定頁（與設定頁「重新開始」一致）；建議先截圖或複製。 |
